# Live context workflow diagnostic — 2026-09-29

This diagnostic exercised the built web application with the configured subscription-backed `gpt-daybreak-blue-latest` profile at requested high reasoning. Both tasks were started and followed through the browser GUI. The local web server used an isolated sessions directory; source review was read-only and the archive task operated on a byte-identical local copy. These are **one run per scenario**, not the three-run acceptance required for a behavioral conclusion. Neither run establishes 100% reliability or Qwen behavior.

This also exposed a quality and efficiency failure before the final validation gate. The generic improvement to evaluate is focused source excerpts, including both suspected sink and effective guards, before promoting a source-only lead; preserve full logs for recall and independent challenge.

The retained finding matters independently of context management: an HTTP client that can reach the web listener can create an intake and persist `full_access` without authentication. The default bind is loopback; actual exposure depends on deployment. Its report explicitly does not claim downstream command execution was exercised. Review and harden the web control plane before any non-loopback deployment.

## Forced result offload and exact recall — follow-up

`internal/workerloop/context_offload_live_test.go` adds an opt-in real-model diagnostic. Each run creates a fresh random verification tag in the stdout file of the oldest of 401 synthetic saved result cards. The tag is absent from the result preview and first model request. A 48 KiB application input ceiling forces that old result card out of the model view; the full authoritative worker packet and log remain local. The task asks the worker to find the exact tag from saved context, cite its registered log reference, and execute no new command.

Three independent Daybreak Blue/high runs (`sessions/context-offload-live-20260929/r1`, `r2`, `r3`) passed in 49, 37, and 41 seconds. The first bounded request omitted 348 result cards; later requests omitted between 349 and 351 while retaining required anchors. Every run persisted all 401 cards with a saved offload count of zero, because omission is a *request projection*, not deletion from authoritative state. The random tags were distinct across runs. Each first request lacked its tag; a later exact recall placed it in the model request, and the final answer contained that tag and the registered log reference. No `cmd-*` execution log was created. Runs used four, three, and three worker requests, with no request exceeding 48,551 content bytes against the 49,152-byte client ceiling. The full deterministic CI, including terminal and web user-flow checks, passed after this test was added.

This is repeatable evidence for worker result-card offloading, local persistence, and exact log rehydration. It is a preloaded synthetic worker packet rather than 401 chronologically executed steps, does not exercise the coordinator's own planning projection, and does not prove retrieval quality in a complex assessment. The next acceptance slice remains a genuinely long multi-worker assessment that changes goals, plans, and evidence over time, followed by a save/resume and Qwen comparison.

## GUI multi-worker pressure diagnostic — follow-up

Assessment `web-assessment-20260929-144632.260484695-000002` ran through the browser at `http://127.0.0.1:8121/` against a separate Daybreak Blue/high profile with an intentionally reduced **48 KiB application input ceiling**. This was a one-run stress diagnostic, not an acceptance run. The configured Qwen 3.8 and Daybreak profiles use 96 KiB and 128 KiB respectively; the stress ceiling must not be mistaken for either model's normal capacity. The read-only task split `internal/context` and `internal/webapp` between two workers. The operator reviewed each source command through the GUI, steered the coordinator during the run, and asked it to conclude after one narrowed follow-up round.

The first two workers failed explicitly while trying to build later model requests: their post-compaction required sections needed 35,542 and 34,535 bytes, versus allowances of 34,663 and 33,578. The coordinator reported that neither worker had established a verified conclusion and delegated two narrower tasks using the preserved logs. The `context-reconstruction-check` worker finished from targeted source and regression-test inspection. It correctly identified that `ModelView` projects from a clone of the authoritative packet, so a later view can restore content **from the retained packet and logs**, not from the lossy view alone. It did not execute `go test` or a 48 KiB boundary test in this assessment. The `webapp-boundary-check` worker again exhausted its post-compaction allowance (34,941 required versus 34,504 allowed). The coordinator's final planning request also failed to fit (39,816 required versus 37,041 allowed). The saved assessment and report therefore ended **incomplete**, with no security findings and an explicit unreconciled-gap notice. This is fail-closed behavior, not successful long-session synthesis.

Across 37 assessment model calls in about 13 minutes, all 31 saved worker requests stayed under 49,152 message-content bytes (largest 48,926). The coordinator's two saved planning requests used 29,125 and 45,779 bytes; its failed final request was not sent. The saved worker packets, command logs, approvals, plans, and operator steering remained available. The browser context debugger displayed separate coordinator and worker turns, exact request availability, ordered packet sections, and section sizes. A post-run chat question in the same session took one additional model call and accurately separated source inspection from executed validation without starting another worker. No source files were changed by the assessment.

The diagnostic reveals a practical floor for the generic 48 KiB profile on broad source-review work. Near failure, a worker view included roughly 13.2 KiB of static behavior guidance, 3.5 KiB of capability inputs, and 7–9 KiB of latest tool output before plans and evidence references. Broad source commands repeatedly saved much larger logs while the worker saw only bounded previews; `rg` was unavailable and one `grep | head` pipeline failed under `pipefail`. These tool errors were visible and the workers adapted, but they consumed calls and context. Any reduction of the protected packet or static guidance needs held-out tests for information loss, rather than a change tailored to this source tree. The next tests should exercise genuinely changing coordinator and worker state at the configured 96/128 KiB ceilings, verify final synthesis and save/resume, and compare retained evidence and runtime cost before changing the projection policy.
