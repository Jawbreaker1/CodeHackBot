# Live context workflow diagnostic — 2026-09-29

This diagnostic exercised the built web application with the configured subscription-backed `gpt-daybreak-blue-latest` profile at requested high reasoning. Both tasks were started and followed through the browser GUI. The local web server used an isolated sessions directory; source review was read-only and the archive task operated on a byte-identical local copy. These are **one run per scenario**, not the three-run acceptance required for a behavioral conclusion. Neither run establishes 100% reliability or Qwen behavior.

This also exposed a quality and efficiency failure before the final validation gate. A source-review worker inferred two vulnerabilities without first obtaining the exact current guard code and a negative control. Its broad source commands produced up to 62 KiB of stdout per command, while the worker's ordinary tool preview shows only the first 8 KiB. The actual `EvalSymlinks` guard was in a saved log, but not in the worker's model-visible excerpt; the `EvalSymlinks` occurrences in later requests were from a search-command pattern, not observed guard code. The worker had a source-review guide and a recall tool. The independent challenge workers corrected the conclusion, at the cost of extra plans and calls. The generic improvement to evaluate is focused source excerpts, including both suspected sink and effective guards, before promoting a source-only lead; preserve full logs for recall and independent challenge.

The retained finding matters independently of context management: an HTTP client that can reach the web listener can create an intake and persist `full_access` without authentication. The default bind is loopback; actual exposure depends on deployment. Its report explicitly does not claim downstream command execution was exercised. Review and harden the web control plane before any non-loopback deployment.

The successful search took about 12 seconds; model and tool orchestration dominated elapsed time. A second worker used 7-Zip, not the first worker's Python extractor, to confirm archive integrity and a private extraction. Both independently produced the same member byte length and SHA-256. The archive copy and original retained SHA-256 `af82d38ac307097ed052739d20487fbbe9231f725993983f62a866ddb49225dd`. This is a successful bounded recovery and handoff, but still an expensive generic workflow for a simple fixture. It does not justify archive-specific planners or a claim of broad password-recovery effectiveness. Measure the decision path on unrelated tasks before changing the agent's strategy or call budget.

## Context and persistence observations

- Each worker had its own saved packet and request sequence. The coordinator had separate saved planning requests and received the prior worker outcomes when assigning verification. The latest operator steering in the code review was present in the final coordinator request.
- The configured Daybreak application input ceiling was **131,072 bytes per request**. Final worker message contents ranged from roughly 88 KiB to 130 KiB, all under that ceiling. Several source-review workers reached 99% of it and still retained goal, scope, active plan, current result, and log references. The full authoritative packets kept their plan revisions and result cards; bounded model views did not overwrite the saved state.
- At these run lengths no old result card or plan revision needed to be removed entirely from the model view. Older output excerpts were shortened under pressure, with a recall note and log reference. The source false leads show why an accessible full log is not enough by itself: the model must request and inspect the decisive portion before claiming what code does.
- The first review used 1,684,627 provider-reported tokens across all calls; the archive run used 485,045. Those figures include model outputs and repeated context, so they are not one context-window measurement. Large recurring evidence excerpts and broad commands remain measurable costs.
- Both assessment records completed, both reports have accessible registered evidence, and saved worker sessions remain available. Report `ready_for_review` checks structure and references, not truth. Independent challenge prevented two false source findings from entering the final report.

## Open acceptance work

Repeat the unchanged tasks and at least one unlike source-analysis task three times each before claiming reliable behavior. Inspect exact requests, restored sessions, false negatives and false positives, and wall-clock/model-call cost. Test a genuinely long, changing session that forces plan and result offloading plus exact recall; these runs approached the byte limit but did not exercise full-card eviction. Test Qwen 3.8 at its configured 70k window separately. Verify provider token capacity rather than equating the application's byte ceiling with the model's token context. Preserve the independent finding challenge and secret-safe evidence handling while improving source focus and decision efficiency.
