# Coordinator result-index smoke, 2026-10-10

This checks context handoff, not ten-worker execution or vulnerability discovery. The reproducible fixture is `TestCoordinatorFanInKeepsEveryCurrentWorkerVisible`; the opt-in Daybreak check is `TestLiveCoordinatorReadsIndexedFanIn`.

The deterministic fixture creates ten completed fictional worker results, each with four large evidence previews, plus an older result and a cited current candidate. At a 48 KiB planning allowance, the coordinator request keeps all ten current worker IDs, statuses, short conclusions, lead hints, the current finding, and its registered citation. The request offloads the previews and uncited paths. Every `result_ref` resolves to a complete saved `tasks/<task-id>/result.json`; the authoritative state is unchanged. An interrupted worker now receives a durable blocked result file before it is included in recovered state. A failed write prevents publication of a dangling reference.

Two Daybreak Blue/high smoke calls used a 29,480-byte indexed packet with ten fictional results. Both responses recognized the early unresolved role-visibility cue, distinguished it from the nine expected observations, claimed no finding, and proposed a narrow saved-result review. The first automated assertion incorrectly required the model to repeat a fixture color label; it failed despite a useful response. The corrected assertion and the runtime decision validator passed on the second call. The registered log references in this model-only fixture are fictional placeholders; no worker executed them or verified the suggested check.

Full CI and the assessment race suite passed. This demonstrates that normal ten-result context pressure need not fail or silently discard a current worker, and that one real model request can plan from the compact index. It does not establish reliable concurrent execution, repeated model quality, or the ability to resolve every lead from offloaded records. Keep the two-worker production limit until those separate gates are tested.
