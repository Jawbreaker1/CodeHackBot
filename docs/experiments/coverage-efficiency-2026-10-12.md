# Coverage context and short-output smokes — 2026-10-12

The prior TCP-service comparison showed that small assessments could take 10–15 minutes and that the coverage reviewer saw only the latest worker batch. An earlier tested path could therefore reappear as an unanswered question. The reviewer now receives up to 12 compact prior worker outcomes, with task status, a bounded summary, and up to three exact evidence references per task. The latest results retain their more detailed cards. A prior result is context about what was tested, not proof that every related variant is safe. The packet test verifies both latest and prior results remain present without copying old raw output into the review prompt.

The first live smoke used the built CLI, saved `gpt-daybreak-blue-latest` subscription profile at high reasoning, and the local fixed document fixture at `http://127.0.0.1:19088`. The operator request allowed only low-impact unauthenticated GET requests to that exact origin and prohibited local source or file inspection. The fixture's independent oracle passed before the run. Session `sessions/assessment-20261012-211052-3353111224/` completed in 578 seconds with 22 model calls, three planning rounds, and nine target GET requests. The final decision contained no reproduced finding; it retained a banner observation as a candidate. Before round three, the saved coverage-question request contained both second-round worker results and a compact first-round outcome, 9,800 bytes in total. The independent reviewer suggested new, narrow questions, and the coordinator documented why it stopped at the selected focused depth instead of treating negative probes as proof of complete safety. This demonstrates context delivery and a reasonable final decision once; it does not establish that the added context caused the model to avoid a repeat or improved detection accuracy.

That run also exposed a simpler worker inefficiency. The first worker used six actions for three GET requests because it saved each short HTTP response and used another model turn to read the file back. Worker guidance now asks for a bounded, non-sensitive status and result in the same action that records an artifact; larger or sensitive outputs still stay in restricted evidence with only a short status. This is a general tool-use instruction and introduces no target-specific branching.

The second built-CLI smoke used the same model and fixture with a narrower three-request operator task. Session `sessions/assessment-20261012-212418-2621698190/` completed in 138 seconds with nine model calls, two planning rounds, three worker actions, and exactly three GET requests. Each action's saved stdout included its request URL, status, relevant headers, and bounded response evidence. The next worker context contained the prior response; there was no readback-only action. The final decision listed 200 for the home page, 200 for the linked public document, and 400 for an empty path value, with no reproduced security finding. The narrower scope prevents a valid before/after speed comparison.

An attempted second smoke in `sessions/assessment-20261012-212310-631772083/` was aborted before target execution after test automation sent several terminal answers in one batch and stale answers entered coordinator chat. It is excluded from outcome and timing claims. The clean rerun sent one answer after each prompt. The temporary fixture listener was stopped after validation. The single persistent BirdHackBot web server was then replaced in place with the rebuilt binary on port 8123; the replacement returned HTTP 200.

These are live workflow smokes, not three-run acceptance evidence. Remaining work is to measure elapsed time and finding quality across repeated held-out vulnerable and fixed targets under matched scopes, and to investigate other sources of excess model turns without weakening independent evidence review.
