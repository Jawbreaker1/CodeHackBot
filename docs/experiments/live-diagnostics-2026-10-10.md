## Harness issues exposed and changes made

- One intake response contained two top-level JSON objects and could not be decoded. `internal/intake/intake.go` now gives an invalid structured response one bounded correction attempt. The rejected response cannot trigger a tool or enter the transcript. A malformed-then-correct response is covered by `internal/intake/intake_test.go`; resubmitting through the live UI succeeded after rebuilding.
- Two workers encountered subscription-bridge 502 failures after collecting partial evidence. The coordinator treated them as failures and planned fresh validation rather than promoting an unsupported conclusion. `internal/llmclient/client.go` now retries a 502/503/504 response once after one second through the normal budget and usage hooks. A 502-then-success response and a non-retried 400 are covered by `internal/llmclient/client_test.go`. The retry branch itself was not observed again in a live run; the fixed-control assessment resumed and completed after the server restart.
- The positive workflow plan proposed two parallel follow-ups that would mutate the same single in-memory document. The operator deselected one to prevent interference. The coordinator planning prompt now says to use isolated test state or sequence tasks that change the same shared target. This is generic guidance, not a workflow-specific runtime lock; its effect on live plans still needs validation.
- The fixed-control session resumed after a server restart, but the coordinator repeated a round summary before continuing. This is a presentation issue, not lost evidence.
- All three tasks were expensive relative to their small synthetic fixtures. The recorded calls and token totals justify a later efficiency investigation; these tests do not identify a single bottleneck that warrants hardcoded task shortcuts.

## Saved-state check

All three `assessment.json` files reached a terminal status. The two protected-artifact worker results were both `done`; the positive web run had discovery `done`, interrupted verification `failed`, and fresh retest `done`; the fixed control had interrupted discovery `failed` and later validation `done`. The positive report lists one reproduced finding, while the other two list none. All 39 saved worker pre-LLM packets contain the core sections with unique names and the behavior frame first. All 50 saved worker/coordinator request snapshots parse as JSON, start with a system message, and remain below the configured 131,072-byte input ceiling; the largest is 81,309 bytes. This checks packet shape and persisted state, not whether every semantic detail in those packets is optimal.

`./scripts/ci.sh` passed after the protocol and transport fixes. Repeated live runs on held-out targets, live validation of the shared-state planning guidance, actual retry observation under a transient outage, and measurements of detection rate, false positives, elapsed time, and model use remain open.

An opt-in direct Daybreak planning probe was added to `internal/assessment/parallelism_live_test.go` for two state-changing questions on one shared document. The first call proposed one sequential task and explicitly noted the shared-state hazard. The second call returned a plan with an invalid `open_leads` record, so the direct probe stopped before a third call and did not pass. This test calls the model and validator directly rather than the production coordinator's correction loop. It therefore documents an unresolved structured-output reliability limit, not a demonstrated failure of the production plan correction path.
