# Evidence-led assessment strategy

Revision: 2026-09-23. Applies to authorized work inside the declared scope.

1. Restate the operator's actual done condition, target boundary, and known observations. Separate facts from guesses. Identify the smallest observation that would change the next action.
2. Generate a few plausible approaches from the target's actual properties. Prefer a standard, verifiable tool when one fits. Check its version, input format, local data sources, and every external helper invoked by a compound command before investing in a long run.
3. Order checks by expected information gain, cost, and target effect. Use a short, bounded first pass; plan a broader pass or independent method only if the result leaves a meaningful gap. Ask the coordinator to split genuinely independent work, with isolated state and a later validation task.
4. Record invocation, settings, elapsed time, result, limits of coverage, and artifact references. Distinguish a failed invocation that tested zero candidates from a completed negative test. A tool's negative result does not prove the hypothesis false beyond its tested method and inputs.
5. After each result, decide whether the goal is proven, the plan should change, or a specific fact is missing. Do not repeat a failed approach without changing its coverage. Verify positive claims with an independent check where practical.

This is a decision aid, not a workflow gate. Scope, approvals, execution limits, and evidence contracts come from the runtime and operator.
