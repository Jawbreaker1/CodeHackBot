# Model tool capabilities

BirdHackBot has three distinct model roles. A tool shown to one role is not automatically callable by another. The prompt catalog in `internal/behavior/frame.go` describes this division to every model; the role-specific prompt supplies the exact JSON contract.

When the operator asks for tools, the coordinator should name the harness operations below. Installed Kali programs are examples of what a worker can invoke through `bash`, not additional built-in model tools.

The configured Qwen profile requests JSON-schema object output for structured control decisions. Ordinary chat replies remain text. This is a provider setting in `config/model-profiles.local.json` (`structured_json: true`), not a parser that guesses meaning from prose.

| Phase | Harness-defined choices | What they can do |
| --- | --- | --- |
| Intake conversation | `list_directory(path)`, `host_system()`, `local_network()`; in connected mode, `dns_lookup(host)`, `web_fetch(url)`, `vulnerability_search(query)`, and optional `web_search(query)` | Under the session approval level, list workspace entry names/types, read fixed host identity or local interface/route/neighbor metadata, look up public DNS, fetch one bounded public page, search NVD, or discover public source pages through local SearXNG. Search hits are leads; the coordinator reads a selected page before citing it. External observation is disabled in air-gapped mode. Intake can also return a goal/scope **proposal** for operator review. |
| Assessment coordinator | Plan worker tasks, revise the plan, converse with the operator; connected public source research in browser and CLI chat | The coordinator delegates target tests to workers. During an assessment it can also discover public source pages through local SearXNG and read an exact public page, under the session approval level. Search snippets are not target evidence. |
| Assessment worker | `bash`, `browser_run`, `metasploit_lookup`, `mcp_list`, `mcp_describe`, `mcp_call`, `load_strategy`, `update_plan`, `ask_user`, `step_complete`, `blocked` | `bash` runs one direct executable or Bash script. `browser_run` runs a task-local Playwright scenario with trace and preview. `metasploit_lookup` reads the installed module catalog. The optional MCP choices discover, inspect, and invoke tools from configured local stdio servers. Each external action shares the approval and evidence path. `load_strategy` loads one local guide. The remaining choices update the plan, ask, finish, or report a blocker. |
| Analysis guide | Saved analysis snapshot; connected NVD search, optional broad web search, and public page reading when useful | Explains one saved assessment or a customer folder. It may search NVD or discover public sources through local SearXNG, then read selected public pages through the shared bounded reader. Those links are background sources, never target-test evidence. External research is unavailable in air-gapped mode. |

Optional [MCP configuration](mcp.md) adds specialist tools without adding a separate implementation for each server. MCP server descriptions and results remain untrusted data; availability and behavior require verification.

`bash` can call verified installed Kali and host tools for source review, local file work, scanning, and advisory research. Nmap, SearchSploit, John, Hashcat, curl, and Metasploit target checks or module runs remain commands rather than separate model tools. `metasploit_lookup({cve})` uses local `search cve:...`; `metasploit_lookup({module})` uses local `info`. It records the exact command and output without parsing console prose. A match is a research lead: the worker must still compare observed software/version and module prerequisites, and any target-contact validation is a separate action under the session approval policy. Module absence does not mean no CVE exists. This lookup works with an installed local Metasploit catalog in air-gapped mode and does not supply current CVE-feed coverage by itself. The optional [software research guide](../strategies/software-research/SKILL.md) lists local and connected advisory sources and when each is useful. Connected sources are unavailable in air-gapped mode; the current installation has no comprehensive local CVE feed. `browser_run` is the dedicated wrapper for the existing [Playwright runner](../../tools/playwright-runner/README.md); workers create and inspect their scenario source with `bash` first. Connected-mode web retrieval must obey scope. Air-gapped mode uses only local resources. A small task-local helper may be built when existing tools are insufficient, with its creation and execution logged as separate commands. Prefer a short shell script for command composition, Python with its standard library for substantial parsing or transformations, and JavaScript for browser scenarios. Declare helper source and validation output as worker artifacts. Those files remain in that assessment's task workspace; another worker can reuse an exact recorded artifact after inspecting its source, verifying its applicability, and obtaining the normal execution approval. Nothing is implicitly promoted across customer sessions.

Report generation belongs to the assessment runtime: it renders the coordinator's structured findings and worker evidence into `report.md` under the assessment session folder. It does not run through `bash` or require the model to invent an output path. The web transcript links to the finished report and analysis view; the customer analysis view links to its unified Markdown report. The [reporting strategy](../strategies/evidence-reporting/SKILL.md) describes the expected executive and technical sections. The saved report is a draft for professional review.

The default session policy asks the operator before every execution. The operator can choose another policy in session settings. When the operator asks to approve each file change, keep that mode at **Ask me before every execution** and use a separate `bash` invocation for each item. Approval exposes the exact invocation; it does not expand scope. The current runtime relies on the authorized VM and operator review rather than an OS-level filesystem sandbox or network allowlist.
